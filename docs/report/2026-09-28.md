Tapi fitur ini **belum bisa jalan end-to-end** karena migration database `036_mayar_payments.sql` **belum diterapkan** ke Supabase.

Alasannya, push kode ke `development` akan memicu Vercel preview build yang langsung error saat checkout karena kolom DB belum ada. Commit kode setelah migration diterapkan (lihat bagian *Langkah Lanjutan*).

### Webhook `POST /api/webhooks/mayar`
1. Token salah/tidak ada → `401`.
2. Payload divalidasi Zod (`event`, `data`) → invalid `400`.
3. Event selain `payment.received` (mis. `payment.reminder`) → `200` diabaikan.
4. Cari payment dari kandidat id di payload (`id`, `transactionId`, `productId`, `paymentLinkId`, `paymentId`, `invoiceId`) terhadap `mayar_payment_id` / `mayar_transaction_id`; fallback `extraData.orderNumber`.
5. Tidak ketemu → `200 {matched:false}` (supaya Mayar berhenti retry).
6. Ketemu → `reconcileMayarPayment`. Kalau error API atau status di Mayar masih `unpaid` → `502` supaya Mayar **retry** (maks 5x).

**Sudah dites di dev server (localhost):** tanpa token → 401, token salah → 401, `payment.reminder` → 200 ignored, id tidak dikenal → 200 matched:false, payload rusak → 400.
**Belum dites:** webhook `payment.received` asli dari Mayar (butuh migration + URL publik).

### 2. Tes lokal (sandbox)
1. `npm run dev` (hapus folder `.next` dulu kalau typecheck mengeluh soal route Midtrans).
2. Checkout satu pesanan → harus diarahkan ke halaman bayar `*.myr.wtf`.
3. Bayar di sandbox Mayar → kembali ke `/dashboard/orders/{id}?payment=return` → status harus jadi **Dibayar**, stok terpotong, shipment Biteship dibuat.
4. Tes webhook: jalankan tunnel, daftarkan URL-nya di dashboard **web.mayar.club** (menu webhook), bisa juga pakai "test webhook" di dashboard:
   ```bash
   cloudflared tunnel --url http://localhost:3000
   ```
   URL: `https://<tunnel>/api/webhooks/mayar`
5. **Cek payload webhook asli** (lihat kolom `payments.raw_response` setelah settle via webhook, atau log server). Pastikan:
   - header `x-callback-token` memang dipakai (kalau 401 terus, cek nama header di dashboard Mayar);
   - salah satu field (`id`/`transactionId`/`productId`/...) cocok dengan `mayar_payment_id` atau `mayar_transaction_id`, atau `extraData.orderNumber` ikut terkirim. Kalau tidak ada yang cocok, webhook akan balas `matched:false` dan perlu penyesuaian di `app/api/webhooks/mayar/route.ts`.
6. Cek nilai `paymentMethod` asli dari transaksi yang sudah dibayar → pastikan `normalizeMayarPaymentMethod` memetakan ke label yang benar (`payments.payment_type`).
7. Tes pembatalan: pesanan pending (link Mayar harus tertutup), pesanan lunas (form rekening wajib → admin dapat notifikasi "Perlu Refund" → admin ubah ke Dikembalikan → user dapat email refund).
8. Tes expiry: pesanan dibiarkan > batas waktu → dibatalkan pg_cron / lazy-cancel.

## Risiko & catatan terbuka

- **Payload & header webhook belum terkonfirmasi** dari webhook asli (lihat langkah 2.5). Ini titik paling mungkin perlu penyesuaian.
- **Rate limit Mayar**: halaman detail order dengan `?payment=return` dan tombol "Saya sudah bayar" memanggil API Mayar. Spam klik bisa kena 429 (user dapat pesan "tidak dapat memverifikasi"; webhook tetap jadi jalur utama).
- **Refund manual** menambah beban admin; pelanggan lama yang bayar via e-wallet/QRIS sekarang juga harus isi rekening bank saat batal.
- **Setting `payment_timeout_hours` > 3 jam diabaikan** (dibatasi 3 jam karena pg_cron). Kalau mau window lebih panjang, ubah juga `interval '3 hours'` di fungsi `expire_pending_payment_orders` (migration 029) dan `MAX_PAYMENT_TIMEOUT_HOURS` di checkout route.
- Login redirect: kalau sesi user habis saat kembali dari Mayar, parameter `?payment=return` hilang setelah login — status tetap terupdate lewat webhook atau tombol "Saya sudah bayar".
- **Bug lama (tidak diubah):** admin membatalkan pesanan `pending_payment` dari panel admin **tidak melepas `reserved` stok** (hanya pesanan lunas yang stoknya dikembalikan) di `app/admin/(panel)/orders/_actions.ts`.
- **Bug lama (tidak diubah):** error lint `react-hooks/purity` dan `react-hooks/set-state-in-effect` di halaman order & checkout.
- Docs lama di `docs/` (audit Midtrans, spec/plan Midtrans) tidak diubah — sudah usang secara isi.
