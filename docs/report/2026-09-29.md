## 3. Turnstile (CAPTCHA) di local dev

**Masalah:** login admin di `geekytech.local:3000` selalu "Verification failed" (`[Cloudflare Turnstile] Error: 600010`), juga di Incognito.

**Diagnosis:** di halaman HTML statis, site key yang sama **lolos** → jaringan/browser/domain aman. Penyebabnya di `components/auth/turnstile-widget.tsx`:
1. React Strict Mode menjalankan effect 2× → widget dirender 2× ke container yang sama (`already been rendered`), cleanup hanya `reset()`.
2. `renderWidget` bergantung pada callback parent. Admin login mengirim `onExpire={() => ...}` inline → identitas baru tiap render → widget dihapus & dibuat ulang **di tengah challenge** → 600010.

**Fix:** callback disimpan di ref (widget dirender sekali per mount), cleanup pakai `turnstile.remove()`, script `?render=explicit` + listener `load` yang dilepas saat cleanup. Terverifikasi: re-render parent 3× → 0 render/remove ulang. **Login sudah berhasil.** Bug ini juga ada di production (komponen dipakai di login, register, admin login).

**Catatan local dev:**
- Buka app lewat **`http://geekytech.local:3000`**, bukan `localhost` (Cloudflare menolak `localhost` sebagai domain widget; alias ada di hosts file + `allowedDevOrigins`).
- `.env.local`: `NEXT_PUBLIC_APP_URL=http://geekytech.local:3000` (dipakai `redirectUrl` Mayar; kalau `localhost`, cookie login tidak ikut setelah kembali dari halaman bayar).

## 4. Nomor resi langsung muncul setelah "Konfirmasi Siap Pickup"

**Temuan:** Biteship menerbitkan waybill **saat konfirmasi**, bukan saat kurir dialokasikan (AWB `WYB-1790668866554` = timestamp 08:01:06, konfirmasi admin 08:01:07). Kode lama tidak menyimpannya → resi baru muncul ~2 menit kemudian via webhook `allocated`.

**Fix:**
- `lib/biteship/confirm-order.ts` — return `waybillId` dari response confirm.
- `app/admin/(panel)/orders/_actions.ts` → `confirmReadyForPickup`: pakai waybill dari confirm, fallback `getBiteshipOrder`; simpan ke `shipments.awb`, catat di riwayat status, return `awb`.
- `confirm-pickup-button.tsx` — toast menampilkan nomor resi.

## 8. Tunnel untuk tes webhook Mayar

- `winget` tidak ada di Windows 10 ini → `cloudflared.exe` diunduh ke `%USERPROFILE%\cloudflared.exe` (rilis resmi GitHub).
- Jalankan (terminal kedua, `npm run dev` tetap jalan):
  ```powershell
  & "$env:USERPROFILE\cloudflared.exe" tunnel --url http://localhost:3000
  ```
- Tunnel siang ini: `https://render-tue-uniprotkb-vienna.trycloudflare.com` — **URL berubah setiap kali cloudflared dijalankan ulang**, daftarkan ulang di web.mayar.club.
- Log `FAIL` untuk `region2.v2.argotunnel.com` bisa diabaikan selama ada `Registered tunnel connection`.
- Sudah dites dari luar: `POST /api/webhooks/mayar` tanpa token → `401 Unauthorized` ✅ (request sampai ke dev server, verifikasi token jalan).
- Kalau pindah jaringan (di rumah) dan `cloudflared` belum ada, unduh lagi:
  ```powershell
  Invoke-WebRequest -Uri "https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe" -OutFile "$env:USERPROFILE\cloudflared.exe"
  ```
